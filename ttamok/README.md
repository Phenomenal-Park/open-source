# 따목 (Ttamok)

오목에 **두 점 따내기**를 더한 바둑판 게임. 같은 화면에서 두 사람이 번갈아 두는 웹 프로토타입이며,
아이디·비밀번호 계정과 ELO 점수(18급~9단)가 걸린 랭크 대국을 지원한다.

## 실행

Node 22.18 이상(TypeScript를 빌드 없이 바로 실행).

```bash
npm install
npm run build && npm start      # http://localhost:8787  (게임 + 계정/랭크 API, 데이터: server/data/db.json)
```

개발 모드: `npm run server`(API, 8787)와 `npm run dev`(Vite, 5173 → /api 프록시)를 함께 띄운다.
서버 없이 `npm run dev`만 띄워도 로컬 2인 대국은 그대로 동작한다(로그인만 안 됨).

## 테스트

```bash
npm run typecheck
npm test              # 규칙 엔진(지시서 §9 1~26) · 점수 체계 · 서버 API
npm run test:e2e      # 실제 브라우저(Playwright): 휴대폰 390×844 / 데스크톱, 클릭·터치, 랭크 대국
npm run simulate:ratings -- 350 2 6000   # 점수 분포 시뮬레이션 [SCALE σ 라운드]
```

## 구조

```text
src/game/        규칙 엔진 (React·브라우저 의존 없음, 서버·향후 AI가 그대로 재사용)
  types.ts config.ts captures.ts victory.ts rules.ts gameState.ts rules.test.ts
src/rating/      점수 체계 (elo.ts, ranks.ts, rating.test.ts)
src/ai/          AI (형세 판단 evaluate.ts, 수읽기 search.ts, 기력 단계 levels.ts, Web Worker)
src/components/  Board · Stone · Scoreboard · GameResult · AccountPanel
server/          계정·랭크 대국 API (node:http, JSON 파일 저장소)
scripts/         점수 분포 시뮬레이션, AI 기력 측정
tests/e2e.mjs    브라우저 E2E
```

엔진 API: `createGame(boardSize)`, `isLegalMove`, `getCapturedStones`, `checkFiveInRow`, `checkCaptureVictory`,
`applyMove`(원본 불변, 둘 수 없으면 같은 객체 반환), `undoMove(history)`, `replayMoves`(서버 검증용).

## 규칙 구현 요점

- 포획은 **이번 착수점 기준**으로만 판정: `P(자기)-상대-상대-자기`, 8방향 각각 독립, 여러 방향 동시 가능.
  판에 `●○○●` 모양이 있다는 것만으로는 잡히지 않는다(자충·소급 포획 없음).
- 처리 순서는 지시서 §6 그대로: 착수 → 포획 수집·동시 제거 → 포획 수 → 포획 승리 → 최종 판에서 5목 → 차례 넘김.
- **정확히 5목만 승리**(§9-15, §11-4). 6목 이상은 둘 수 있으나 승리가 아니다. `overlineWins: true` 설정으로 바꿀 수 있다.
  같은 수에서 한 축은 6목, 다른 축은 정확히 5목이면 그 5목으로 승리.
- 금수 없음(33·44·장목 모두 허용, 흑백 동일).
- 포획 승리: 흑 **12개**, 백 **10개** 이상. 같은 수에 포획 승리와 5목을 함께 달성하면 `winReason = "capture"`(처리 순서상 먼저), 5목 줄도 기록.
- 판 크기는 설정값(기본 15, 5~25). 화면에서 13/15/19 선택 가능. 랭크 대국은 점수가 섞이지 않게 15×15로 고정.
- 무르기: 매 수의 불변 스냅샷을 이력으로 보관 → 돌·따낸 돌·포획 수·차례·승패가 모두 복원.

## 점수 체계 (src/rating/elo.ts)

| 항목 | 값 |
|---|---|
| 급·단 | 18급 500점부터 65점마다 한 급(1급 1605점), 1단 1700점부터 100점마다 한 단, **9단 2500점** |
| 시작 | 표시 점수 500점(18급), 하한 0점 |
| 실력 점수(비공개) | 표준 ELO, 1500점 시작, 기대승률 `1/(1+10^(Δ/350))`, K = 64(10판 미만)/40(30판 미만)/24 |
| 승급 보너스 | 표시 점수가 실력 점수보다 낮은 동안: 승리 시 +80(1000점 미만)/+50(1500점 미만)/+25, 패배 시 0(1000점 미만)/절반(1500점 미만) |
| 연승 | 보너스 배율 2연승 ×1.25 … 5연승 이상 ×2 |
| 고단자 이변 | 7단(2300점) 이상이 실력 점수가 낮은 상대에게 지면 점수 이동 ×2.5 (같은 만큼 상대가 받음, 제로섬) |
| 정기 보정 | 서버 시작 시 + 하루 1회: 9단 비율이 0.05~0.1%를 벗어나면 1500점 기준으로 폭을 조정(1회 최대 ±5%, 순위 불변) |

표시 점수는 실력 점수를 넘지 않는다. 보너스는 "자기 실력까지 따라잡기"에만 쓰이므로 많이 둔다고 점수가 부풀지 않는다.
시뮬레이션(가입 7만 명, 실력 분포 폭 σ 1.5~3 가정): 9단 비율 0.07~0.1% 유지, 표시 점수 중앙값 4급(전체)·3급(20판 이상).

## AI (src/ai)

알파베타 수읽기 + 형세 판단(5칸 창 줄 모양, 따내기 진행도, 따일 위험). 규칙 판정은 엔진(src/game)을 그대로 쓴다.
브라우저 Web Worker에서 돌아 화면이 멈추지 않는다. 가장 센 단계도 한 수 0.3초 안팎. AI 대국은 점수에 반영하지 않는다.

| 단계 | 표시(임시) | 측정 간격 |
|---|---|---|
| 1 | 18급 (500) | 기준(추정) |
| 2 | 16급 (690) | +188 |
| 3 | 12급 (900) | +211 |
| 4 | 10급 (1070) | +167 |
| 5 | 7급 (1250) | +188 |
| 6 | 3급 (1490) | +236 |

- 간격: 이웃 단계끼리 흑백 번갈아 40판 → 승률을 실력 점수 공식(SCALE 350)으로 환산(단계당 오차 약 ±80점).
  `node scripts/calibrate-ai.ts <약한 번호> <강한 번호> [판 수]`
- 출발점(가장 약한 단계 = 18급)은 추정. 사람과의 대국이 쌓이면 실측으로 고친다.
- 한계: 수읽기를 5수로 늘려도 4수와 승률 50%로 차이가 없었다. 3급 위로 가려면 형세 판단·연속 위협 탐색 개선이 필요.
  AI끼리 대국은 대부분 오목으로 끝나고 따내기 승리는 드물다(측정 200판 중 약 5%).

## 아직 정하지 않은 것 (지시서에 없어 임의로 보완하지 않음)

- 판이 가득 차서 둘 곳이 없을 때(무승부 규칙 없음): 대국이 끝나지 않은 채 멈춘다.
- 상대의 포획으로 내 6목이 정확히 5목이 된 경우: 내 착수로 만든 5목이 아니므로 승리 처리하지 않는다(착수점 기준 판정).
- 랭크 대국 중도 포기: 결과를 내지 않은 대국은 24시간 뒤 사라지고 점수는 바뀌지 않는다.
- 같은 화면 랭크 대국은 한 사람이 두 계정을 만들어 점수를 올릴 수 있다. 온라인 대전·매칭 단계에서 막는다.
